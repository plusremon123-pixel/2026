# 이서현 포트폴리오 설계안

상태: 구현 전 콘텐츠·UX 설계 초안  
기준 자료: `경력기술서_20250418_이서현.docx`, 기존 포트폴리오 PDF, 사용자 확정 프로젝트 목록

## 1. 사이트가 해야 할 일

### 대상

- 경력직 UI/UX·서비스 기획자를 채용하는 실무 리더
- 프로젝트의 결과물뿐 아니라 문제 정의, 협업 범위, 판단 근거를 확인하려는 면접관

### 한 가지 핵심 목표

방문자가 짧은 시간 안에 이서현을 **복잡한 서비스와 운영 구조를 사용자 관점에서 정리하고, 실제 실행까지 연결하는 시니어 UI/UX 기획자**로 이해하게 한다.

### 핵심 메시지

> 화면을 설계하기 전에, 무엇이 진짜 문제인지 정의합니다.

보조 메시지:

> 신규 구축부터 리뉴얼, 장기 운영까지. 사용자와 비즈니스, 운영 조직 사이의 복잡한 조건을 실제로 작동하는 서비스 경험으로 정리해 왔습니다.

## 2. 콘텐츠 신뢰도 규칙

사이트 콘텐츠는 아래 세 상태로 관리한다.

- `confirmed`: 경력기술서 또는 사용자가 확인한 사실
- `draft`: 확인된 업무 범위를 바탕으로 재구성한 설명
- `needs-review`: 정확한 수행 과정이나 결과 확인이 필요한 문장

정량 성과, 사용자 조사, 전환율 개선, 업무 시간 단축 등은 확인 자료가 없으면 작성하지 않는다. 수치가 없는 프로젝트는 구조적 변화, 협업 결과, 산출물과 운영 방식의 변화를 중심으로 설명한다.

## 3. 메뉴와 정보구조

```text

```

- 이름 클릭: Home
- Projects: Featured Work, Operational UX, 전체 프로젝트 통합
- About: 소개, 핵심 역량, Career Timeline 통합
- Contact: 이메일과 연락 안내

## 4. 디자인 시스템 방향

### 콘셉트

`Decision Archive × UX Editorial`

- 구조는 빠르게 훑을 수 있는 의사결정 아카이브
- 프로젝트 도입부는 문제를 한 문장으로 압축하는 에디토리얼 스프레드
- 큰 프로젝트 이미지, 한국어 문장, 여백을 중심으로 구성
- 카드, 배지, 그라데이션, 글로우를 시각 언어로 사용하지 않음

### 시그니처 요소

프로젝트 상세의 `Decision Log`가 유일한 강한 시각 장치다. 사용자가 스크롤하면 현재 읽고 있는 근거·결정·적용 화면의 연결 상태가 조용히 갱신된다.

### 컬러 토큰

| 역할 | 이름 | 값 | 사용 |
|---|---|---:|---|
| Background | Paper White | `#F6F7F5` | 전체 배경 |
| Primary text | Ink | `#161A1D` | 제목·본문 |
| Secondary text | Slate | `#596169` | 메타 정보·캡션 |
| Divider | Rule | `#CED2CF` | 구조 구분선 |
| Decision | Decision Blue | `#2457D6` | 검증된 UX 결정·링크 |
| Thesis | Editorial Plum | `#6E3558` | 핵심 질문·인사이트 |

파랑과 자두색은 같은 화면에서 경쟁시키지 않는다. 파랑은 결정과 이동, 자두색은 프로젝트를 여는 핵심 문장에만 사용한다.

### 타이포그래피

- 핵심 문제·인사이트: `MaruBuri`, 600
- 제목·한국어 본문: `Pretendard`, 400–700
- 기간·역할·수치·Decision Log: `IBM Plex Mono`, 400–500
- 본문 기본 크기: PC 18px / 모바일 16–17px
- 긴 본문의 최대 행 길이: 한국어 기준 약 38–44자

### 자기 검토

초기 A안의 얇은 선과 무채색 보고서 구조만 사용하면 최근 포트폴리오에서 흔한 아카이브 템플릿처럼 보일 수 있다. 이를 피하기 위해 프로젝트를 번호가 아닌 **핵심 질문 문장**으로 기억하게 하고, MaruBuri는 장식적 대형 제목이 아니라 실제 문제 정의에만 사용한다. 구조적 라인은 정보 연결에 필요한 곳에만 남긴다.

## 5. 대표 프로젝트 구성

### Featured 01 — 대교 눈높이 국어 리뉴얼

#### 확인된 정보

- 기간: 2023.12–2024.04
- 역할: 스코어국어 UI/UX 기획, Front App
- 기여 범위: 앱 100%, LMS 일부 참여
- 도구: Figma
- 성격: 초등 저학년 대상 태블릿 학습 서비스 리뉴얼
- 교육과정 개정 반영 및 UI 개선

#### Thesis 초안 — 확인 필요

> 교육과정의 변화를 화면에 반영하는 것만으로는 충분하지 않았습니다. 저학년 사용자가 스스로 다음 학습 행동을 이해할 수 있어야 했습니다.

#### 문제 정의 초안 — 확인 필요

- 교육과정 개정으로 콘텐츠와 학습 단계가 달라져 기존 흐름의 재정리가 필요했다.
- 실제 사용자는 저학년 아동이지만 서비스 선택과 학습 관리는 학부모가 함께 관여한다.
- 고객과 개발 조직이 화면 진행 상태를 명확히 이해할 수 있는 산출물이 필요했다.

#### Decision Log 초안 — 확인 필요

1. 저학년이 다음 행동을 예측할 수 있도록 학습 단계와 피드백의 표현을 일관되게 구성한다.
2. 아동의 학습 흐름과 학부모가 확인해야 할 정보를 서로 다른 우선순위로 정리한다.
3. Figma 프로토타입으로 화면 간 상태 변화를 연결해 고객·개발 간 해석 차이를 줄인다.

#### 결과 표현 초안 — 확인 필요

교육과정 개정 내용을 태블릿 학습 흐름에 반영하고, 주요 상태와 이동 과정을 프로토타입으로 명확하게 전달했다.

### Featured 02 — U+ 스마트상담/스마트가입 웹 서비스 리뉴얼

#### 확인된 정보

- 기간: 2019.09–2020.01
- 역할: PL, 제안·컨설팅, UI/UX 리뉴얼 기획
- 담당 영역: Front / Admin
- 도구: PPT
- 성격: 상담·가입 지원 웹 서비스 리뉴얼

#### Thesis 초안 — 확인 필요

> 상담 화면의 목적은 정보를 많이 보여주는 것이 아니라, 복잡한 통신상품 안에서 고객에게 맞는 다음 선택을 확신하게 하는 것이었습니다.

#### 문제 정의 초안 — 확인 필요

- 상품, 가입 조건, 결합 관계 등 상담 과정에서 다뤄야 할 정보가 복잡하다.
- 상담 직원의 업무 흐름과 고객에게 설명되는 흐름이 동시에 고려되어야 한다.
- Front와 Admin의 정보가 일치하지 않으면 상담 품질과 운영 효율에 영향을 줄 수 있다.

#### Decision Log 초안 — 확인 필요

1. 상담 단계별로 필요한 정보와 선택지를 구분한다.
2. 고객 설명에 필요한 정보와 내부 처리 정보를 같은 화면 위계로 섞지 않는다.
3. Front의 상담 흐름과 Admin의 상품·정책 관리 구조를 함께 검토한다.

#### 결과 표현 초안 — 확인 필요

제안과 컨설팅 단계부터 참여해 상담·가입 과정의 주요 화면과 운영 구조를 하나의 리뉴얼 방향으로 정리했다.

### Featured 03 — Avon.com 통합 리뉴얼

#### 확인된 정보

- 기간: 2019.02–2020.06
- 고객사: LG생활건강
- 역할: UI/UX 기획 및 PL
- 담당 영역: Front 공통 / Admin
- 투입률: 50%
- 도구: PPT, Figma
- 성격: 미국 화장품 회사 Avon.com 통합 리뉴얼

#### Thesis 초안 — 확인 필요

> 통합은 화면을 하나로 만드는 일이 아니라, 공통 기준과 지역·운영별 예외가 함께 작동할 수 있는 구조를 만드는 일이었습니다.

#### 문제 정의 초안 — 확인 필요

- 여러 서비스 또는 운영 영역을 통합할 공통 UI·정책 기준이 필요했다.
- 고객이 사용하는 Front와 운영자가 관리하는 Admin이 함께 정리되어야 했다.
- 장기 프로젝트 과정에서 기획 수정과 PL 역할을 병행해야 했다.

#### Decision Log 초안 — 확인 필요

1. 공통으로 유지해야 할 요소와 운영상 달라질 수 있는 요소를 분리한다.
2. Front 화면의 콘텐츠 구조가 Admin 등록 구조와 연결되도록 설계한다.
3. 변경 요청을 개별 화면 수정이 아니라 공통 원칙과 영향 범위로 관리한다.

#### 결과 표현 초안 — 확인 필요

Front 공통 영역과 Admin 기획을 연결하고, 프로젝트 후반에는 PL 역할을 맡아 변경 범위와 산출물을 조율했다.

### Featured 04 — 하나캐피탈 앱 리뉴얼

#### 확인된 정보

- 기간: 2020.07–2020.10
- 역할: UI/UX 기획
- 담당 영역: Front, 부동산 대출 Part
- 투입률: 100%
- 도구: PPT

#### Thesis 초안 — 확인 필요

> 대출 과정의 복잡성을 감추는 것이 아니라, 사용자가 지금 무엇을 확인하고 결정해야 하는지 이해할 수 있도록 순서를 다시 세웠습니다.

#### 문제 정의 초안 — 확인 필요

- 부동산 대출에는 조건, 한도, 서류, 심사 등 여러 단계와 예외가 존재한다.
- 사용자가 현재 단계와 이후 필요한 행동을 명확히 이해해야 한다.
- 금융 서비스 특성상 이해하기 쉬운 표현과 정확한 정보 전달이 동시에 필요하다.

#### Decision Log 초안 — 확인 필요

1. 업무 정책을 사용자 행동 순서로 번역한다.
2. 입력, 확인, 동의, 결과 단계의 목적을 명확히 분리한다.
3. 필수 안내는 단순 축약하지 않고 사용자가 결정하는 시점에 배치한다.

#### 결과 표현 초안 — 확인 필요

부동산 대출 Part의 정책과 화면 흐름을 모바일 사용 맥락에 맞춰 재구성하고 Front 화면설계를 완성했다.

### Featured 05 — 식품산업 비즈니스 플랫폼

#### 확인된 정보

- 기간: 2023.07–2023.11
- 고객사: 한국식품산업클러스터진흥원
- 역할: UI/UX 기획
- 담당 영역: Front 100%
- 도구: Figma
- 성격: 공급기업과 식품산업 수요자를 교육·사업으로 연결하는 신규 플랫폼
- 사용자 계층별 권한과 프로세스 설계 경험

#### 확인이 필요한 사실

- 기존 PDF에는 BackAdmin 100%로도 표기되어 있어 실제 담당 범위 확인 필요
- 비즈니스 플랫폼과 디지털 플랫폼이 한 프로젝트인지 별도 프로젝트인지 확인 필요

#### Thesis 초안 — 확인 필요

> 하나의 플랫폼이었지만, 공급기업과 수요기업, 운영자는 서로 다른 시작점과 목표를 가지고 있었습니다.

#### 문제 정의 초안 — 확인 필요

- 서로 다른 목적을 가진 사용자들이 교육, 요청, 사업 연결 과정에 참여한다.
- 사용자 유형과 진행 상태에 따라 접근 가능한 기능과 정보가 달라진다.
- 신규 서비스이므로 기능 목록보다 관계와 전체 프로세스를 먼저 정의해야 했다.

#### Decision Log 초안 — 확인 필요

1. 공급기업, 수요기업, 운영자의 목표와 권한을 구분한다.
2. 요청부터 연결까지의 상태와 다음 행동을 일관된 언어로 표현한다.
3. 교육과 사업 연결 기능이 별개의 메뉴가 아니라 사용자 목적 안에서 이어지도록 구성한다.

#### 결과 표현 초안 — 확인 필요

다양한 사용자 계층과 권한을 구조화하고, 교육·요청·사업 연결이 이어지는 신규 플랫폼의 Front 경험을 설계했다.

## 7. 프로젝트 아카이브

아카이브는 상단 메뉴로 분리하지 않고 Projects 페이지 하단에 배치한다.

### 산업 필터

## 9. 반응형 규칙

### Tablet · 768–1199px

- 12열을 8열로 전환
- Project Detail의 고정 Decision Log를 본문 위 가로 목차로 전환
- 대표 이미지와 텍스트 비율을 5:3으로 유지
- 프로젝트 메타 정보는 2열 정의 목록으로 표시

### Mobile · 360–767px

```text
┌──────────────────────┐
│ 이서현          Menu │
├──────────────────────┤
│ 화면을 설계하기 전에│
│ 무엇이 진짜 문제인지│
│ 정의합니다.          │
├──────────────────────┤
│ [프로젝트 이미지]    │
│ 산업 · 기간          │
│ 프로젝트명           │
│ 핵심 문제 2–3줄      │
├──────────────────────┤
│ 다음 프로젝트        │
└──────────────────────┘
```

- 햄버거 메뉴에는 `Projects / About / Contact`만 표시
- 프로젝트 상세는 `Thesis → Overview → 핵심 결정 3개 → 본문` 순서
- Decision Log는 현재 위치 표시가 있는 가로 스크롤 목차로 전환
- 전체 프로젝트 표는 `프로젝트명 / 역할·기간`의 두 줄 인덱스로 전환
- 이미지 주석은 hover에 의존하지 않고 탭 또는 항상 보이는 캡션으로 제공

## 10. 인터랙션 원칙

- 페이지 전환: 180–240ms opacity + 8px 이내 이동
- 프로젝트 인덱스 hover: 이미지 확대 대신 핵심 문장이 `문제 → 결정`으로 교체
- Decision Log: 현재 섹션만 파랑으로 활성화
- 이미지: 클릭 시 고해상도 집중 보기, ESC와 키보드 탐색 지원
- 스크롤 애니메이션은 Thesis Spread 한 곳에 집중
- `prefers-reduced-motion`에서는 모든 이동 애니메이션 제거
- 포커스 링을 숨기지 않으며 최소 44px 터치 영역 확보

## 11. 구현 시 콘텐츠 구조

디자인과 콘텐츠를 분리해 이후 문장과 이미지만 수정할 수 있게 한다.

```ts
type ReviewState = "confirmed" | "draft" | "needs-review";

type Project = {
  slug: string;
  title: string;
  industry: string;
  period: string;
  role: string[];
  scope: string[];
  thesis: string;
  overview: string;
  problems: string[];
  decisions: Array<{
    evidence: string;
    decision: string;
    application: string;
  }>;
  screens: Array<{
    src: string;
    alt: string;
    caption: string;
  }>;
  impact: string[];
  retrospective: string;
  review: Record<string, ReviewState>;
};
```

## 12. 구현 전 확인 항목

문장이 완성되지 않아도 구현은 시작할 수 있다. 아래 항목은 콘텐츠 데이터에서 `needs-review` 상태로 유지한다.

- 웅진씽크빅 프로젝트 종료 여부와 정확한 기간
- 식품산업 플랫폼의 Admin 담당 범위
- 식품산업 비즈니스 플랫폼과 디지털 플랫폼의 관계
- 각 대표 프로젝트의 공개 가능한 화면 이미지
- Avon 통합 범위와 글로벌·지역별 정책 처리 경험
- 하나캐피탈 대출 과정에서 직접 설계한 핵심 단계
- U+ 스마트상담/스마트가입의 실제 사용자와 가장 큰 기존 문제
- 대교 프로젝트에서 저학년 사용성을 위해 직접 결정한 사항
- 공개 가능한 이메일과 외부 프로필 링크

개인 주소, 주민등록번호, 급여, 입사 가능일, 개인 전화번호는 사이트 데이터에 포함하지 않는다.
